Author reusable explanations and play them as progressive native pressure strokes in a separate audience window.

---

Edit the presentation title and cues, add or reorder beats, and use the native draw tool in the scratch canvas. **Capture strokes into selected beat** appends the drawings in canvas order with their recorded pressure. Captured strokes are removed from the scratch canvas after validation; out-of-bounds drawings stay there with an error. Text actions have editable text, coordinates, and timing. Set start and duration in milliseconds to arrange each beat, which holds automatically for narration. Canvas dimensions come from the document; the default is 900 × 680. Captured colors outside black, blue, green, and red map to black. Native stroke geometry and pressure are retained; stroke styling uses the presentation's medium pen style.

The current draft and named saved presentations persist in this browser's local storage. **Save presentation** updates the chosen save; **Save a copy** creates another entry. Import/export JSON is available as a secondary interchange flow. Invalid imports retain both the current document and the invalid JSON, with a validation error. Storage failures show an error; export JSON to retain a portable copy. Scratch drawings are temporary until captured.

Choose **Rehearse this deck** to snapshot the selected document for playback. Open the audience window and share only that window. Draft edits, imports, saved-deck selection, and assistant replacement never change an active rehearsal. Choosing **Rehearse this deck** again explicitly replaces it and resets its prepared shapes. **Space** or **Right arrow** starts the next beat, **P** pauses/resumes, and **R** resets; buttons offer the same controls. Hotkeys are ignored while authoring or editing text. Reset followed by start replays the current rehearsal.

The audience uses `/presenter-canvas/full?audience=1`, without the example wrapper or presenter controls. Its playback clock is local and needs no model request for each stroke. Same-origin, opener/source, and session checks bind the connection. The complete validated document is sent at initialization. Leaving or reloading the presenter pauses playback. Reconnection recovers the audience's document and cue without resetting the drawing. Heartbeat loss disables controls after approximately two seconds; background throttling may delay this. A replacement window starts a fresh rehearsal using the selected rehearsal document and leaves the old window untouched. Audience reload starts fresh; closing and reopening the presenter tab loses the old window session. Native completed shapes remain editable in the audience, and reset removes only presentation-owned shapes.

`document.ts` exposes `presentationSchema`, `parsePresentation(unknown)`, and schema-derived `PresentationDocument`. The version 1 format is `{ version, title, canvas: { width, height }, beats: [{ id, title, note, actions }] }`. Each action is either `{ kind: 'stroke', color, start, duration, points: [{ x, y, pressure }] }` or `{ kind: 'text', text, x, y, start, duration }`. Coordinates use canvas pixels; pressure is 0–1; beat IDs are unique. The parser rejects unsupported versions, fields, actions, invalid timing/pressure, and coordinates outside the declared canvas, returning detached validated data. `sampleDocument` in `prepared.ts` provides a complete example. `createPreparedScene(editor, document)` maps any validated document to the same native draw/text runtime; `AudienceSession` preserves the current deck unless explicitly replaced.

Connect Codex to the dedicated local MCP server once with `codex mcp add tldraw_presenter --url http://127.0.0.1:5481/mcp`. Start the service from the repository root with `pnpm --filter mcp-app dev:presenter`, and start the browser app with `pnpm --filter examples.tldraw.com dev --port 5420`. Open `/presenter-canvas/full` and ask Codex to use tldraw presenter to draw an explanation. The tools expose the document schema, current draft, validation preview, optimistic submission and browser status. The browser receives new server drafts automatically, validates before applying, and saves its current draft locally. A completed drawing preview appears on this page. Rehearse this deck explicitly selects it for audience playback. Manual editing is available under Edit beats and drawings.

The MCP service binds only to loopback and accepts this local example origin. Server drafts are memory-only; browser local saves and JSON exports retain presentations across service restarts. Browser acknowledgements distinguish accepted draft revisions from the independently active rehearsal. They do not prove that a drawing has been visibly rendered. The development window authoring bridge remains available for diagnostics. There is no embedded model, microphone, or native input injection.
